# 마지막 두 상자 · 첫 계약 제작 계획

> **실행 담당자**는 작업별 검토 방식이면 `superpowers:subagent-driven-development`, 한 세션에서 진행하면 `superpowers:executing-plans`를 사용한다. 아래 체크박스는 구현과 검증이 끝날 때 표시한다.

**목표**　씨알·타래·도금이로 복숭아 캔 10상자를 출항 전까지 선적하는 독립 웹 게임 한 판을 만든다.

**구조**　계약 규칙과 시계를 브라우저 화면에서 분리한다. 출항 준비 때부터 재도전까지 같은 상태를 화면과 테스트가 사용한다. 파일과 실행 명령의 기준 디렉터리는 `game-edition/`이다.

**기술**　프로젝트의 Node.js 22 이상, ES 모듈, HTML·CSS, 기본 테스트 러너와 설치된 Playwright를 사용한다.

**기획 근거**　[마지막 두 상자 설계서](../specs/2026-11-20-contract-defense-design.md) · [게임 승인 원화 목록](../../../current/artwork.json)

## 공통 조건

- 한 판은 운행 시간 180초, 두 경로, 출하량 4·4·2상자, 시작 운송비 3칸이다. 준비·선택 중에는 운행 시간이 흐르지 않는다.
- 첫 배치는 무료다. 출발 뒤 이동과 도장 즉시 처리에 각각 1칸, 달팽이가 있는 줄로 이동할 때 추가 1칸을 쓴다. 운송비가 없어도 운행은 계속된다.
- 마지막 두 상자와 약속 자리를 출발 전에 표시한다. 도금이의 궁극기는 한 번, 원하는 순간에 발동한다. 마감과 동시에 도착한 상자도 선적한다.
- 승인 원화 세 장을 기존 경로에서 읽는다. 적·경로·강판 다리는 표식으로 표현한다. 첫 시제품은 본편 세이브·재화와 독립적으로 실행한다. 두 번째 계약과 승리 일러스트는 첫 판의 플레이 검토 이후 범위다.

## 검토할 다섯 장면

| 플레이 상황 | 확인할 결과 | 담당 작업 |
| --- | --- | --- |
| 마감 직전에 화면 갱신이 늦어짐 | 180초에 닿은 상자까지 한 번만 집계 | 1 |
| 달팽이가 있는 줄로 옮길 예산이 부족함 | 친구의 위치·비용·약속이 모두 유지됨 | 2·3 |
| 도금이가 1/2를 지킨 뒤 다른 자리를 눌렀다가 취소 | 경고만 보이고 약속과 시각이 유지됨 | 3·4 |
| 표시 상자 하나가 이미 선적된 뒤 궁극기를 연속 입력 | 남은 상자 하나만 건너고 사용 횟수는 한 번 | 3 |
| 만료 직후 같은 계약에 재도전 | 첫 배치·운송비·시계·약속 모두 초기화되고 시간이 두 배로 흐르지 않음 | 4 |

## 1. 두 줄에서 움직이는 첫 계약

**생성 파일**　`spinoffs/contract-defense/first-contract.mjs`에 시간표와 비용, `simulation.mjs`에 상태 전이, 같은 디렉터리의 `simulation.test.mjs`에 결정적 테스트를 둔다.

**인터페이스**　`createContract() → state`, `start(state)`, `advance(state, milliseconds)`를 내보낸다. 상태에는 `phase`(준비·운행·결과), `elapsedMs`, 예산, 친구 위치, 고유 ID가 있는 상자 열 개와 선적 결과가 들어간다. 코드는 각 상자의 마지막 통과 지점을 기억한다.

- [x] 테스트를 먼저 작성한다. 같은 배치로 20초를 한 번 진행하거나 1초씩 20번 진행한 결과가 같다. 준비 중 20초는 시계를 움직이지 않는다. 180,000ms 도착과 180,001ms 도착의 최종 선적 수 차이는 1이다.
- [x] `node --test spinoffs/contract-defense/simulation.test.mjs`로 구현 전 실패를 확인한다.
- [x] 시간표와 상태 전이를 구현한다. 긴 프레임도 예정 사건과 마감 시각을 차례로 처리한다. 같은 시각에는 검사대 통과·부두 도착·선적 후 마감을 판정한다.
- [x] 첫 조정값으로 0·60·140초에 웨이브를 열고, 마지막 두 상자는 같은 줄로 140·148초에 내보낸다. 검사대까지 12초, 그 뒤 일반 경로 16초, 막히면 추가 12초, 다리로는 남은 길 최대 3초로 시작한다. 이 값이면 두 번째 상자는 일반 경로로 176초, 막히면 188초 도착이라 선택에 따라 결과가 달라진다.
- [x] 같은 명령으로 모두 통과하면 시간표·시뮬레이션·테스트를 한 변경으로 기록한다.

## 2. 장애물에 맞춰 친구를 배치하는 한 수

**수정 파일**　`first-contract.mjs`, `simulation.mjs`, `simulation.test.mjs`. 경로별 친구 자리는 종류별 하나씩 두어 세 친구가 한 줄에 서도 된다.

**인터페이스**　`previewMove(state, friendId, lane) → {cost, allowed, breaksPromise}`, `move(state, friendId, lane) → boolean`, `payInspection(state, cargoId) → boolean`. 예고·진입·통과·해제는 1번의 운행 시각을 사용한다.

- [x] 같은 줄에 둔 씨알이 검사대 전 도장을 제거하는 경우, 도금이가 첫 도장을 막는 경우, 타래가 붙잡은 달팽이를 자리를 떠나며 놓아주는 경우를 각각 테스트한다. 도장이 남은 수레에 1칸을 쓰면 대기가 끝나고 두 번째 결제는 거절돼야 한다.
- [x] 이동 비용을 테스트한다. 준비 중 0, 출발 후 일반 줄 1, 달팽이 줄 2다. 예산 1에서 2칸짜리 이동을 시도할 때 `move(...) === false`이며 전후 예산과 위치가 같다.
- [x] 1번의 테스트 명령으로 실패를 확인한 뒤 일반 행동과 장애물의 경로 상호작용을 구현한다. 첫 웨이브에는 달팽이, 두 번째에는 심판관을 예고하고, 마지막에는 달팽이가 표시 상자의 검사대 이후 구간을 늦추게 한다. 달팽이가 막는 줄에 타래를 둔 경우 수레는 앞지를 수 있다.
- [x] 예산 0에서 수레가 계속 움직이고 도장이 자연 해제되는 테스트까지 통과하면 이 단위로 기록한다.

## 3. 약속을 지키거나 포기하는 마지막 웨이브

**수정 파일**　`simulation.mjs`, `simulation.test.mjs`. **추가 파일**　`spinoffs/contract-defense/outcomes.test.mjs`에 같은 계약을 처음부터 구동하는 세 가지 플레이를 둔다.

**인터페이스**　`selectFriend(state, friendId)`, `cancelSelection(state)`, `useBridge(state) → boolean`. 약속 상태는 `waiting → guarding → ready → used` 또는 `broken`이다. 검사대를 지난 표시 상자 ID로 0/2·1/2를 계산한다.

- [x] 마지막 웨이브 시작 시 지정 자리가 비면 약속 실패, 그 전의 이동은 허용, 1/2에서 미리보기와 취소는 상태 보존, 실제 이탈만 실패라는 네 경우를 테스트한다. 선택 중 `advance(state, 30000)`을 호출해도 도착·시각·재사용 시간이 그대로여야 한다.
- [x] 이미 하나 선적한 시점에 궁극기를 두 번 시도한다. 첫 확정만 성공하고 남은 표시 상자 한 개만 경로를 바꾼다. 이미 도착한 ID와 일반 상자의 경로는 그대로다.
- [x] `node --test spinoffs/contract-defense/*.test.mjs`에서 실패를 확인하고 전이를 구현한다. 취소와 행동 확정 직후 시계를 재개하며, 예산 부족이나 잘못된 명령은 선택 상태에서 바로잡을 수 있게 한다.
- [x] 실제 시간표와 공개 행동으로 세 결말을 재현한다. ① 마지막 줄의 타래가 길을 열어 약속이 깨져도 일반 선적으로 승리 ② 도금이는 자리를 지키고 타래는 반대편에 있어 다리로 역전 ③ ②와 같은 배치에서 발동을 놓쳐 마감 미달. 각 플레이는 `createContract()`에서 시작하고 중간 상태 주입 없이 결과·선적 수·남은 상자의 위치를 단언한다.
- [x] 세 경우가 같은 시간표에서 통과하면 약속·결말 테스트를 함께 기록한다. 막히는 지점은 시간표에서 조정하고 모든 경로를 다시 확인한다.

## 4. 브라우저에서 준비부터 재도전까지

**생성 파일**　`spinoffs/contract-defense/index.html`, `style.css`, `app.mjs`, `browser.spec.mjs`, `playwright.config.mjs`. 화면은 1~3번 인터페이스를 호출하며 `requestAnimationFrame`의 실제 경과분을 전달한다. 백그라운드에서는 운행을 멈추고 복귀 시 기준 시각을 새로 잡는다.

- [x] 브라우저 테스트로 출발 전 조건·효과·약속 자리·상자 두 개 표시, ‘도금이에게 맡기기’, 선택 시 정지, 이동 경고 뒤 취소, 궁극기 확정, 선적 결과와 재도전을 사용자에게 보이는 버튼·텍스트로 확인한다. 설치된 Playwright의 페이지 시계로 시간을 진행한다. 재도전 뒤 1초를 진행하면 운행 시각도 1초여야 한다.
- [x] 전용 설정은 이 폴더의 `browser.spec.mjs`만 실행하고 `game-edition/`을 정적 서버 루트로 사용한다. `npx --no-install playwright test --config spinoffs/contract-defense/playwright.config.mjs`로 화면 구현 전 실패를 확인한다.
- [x] 준비 화면에는 10상자·3분·예고·궁극기와 무료 배치를, 운행 화면에는 두 줄·검사대·부두·예산·약속 진행을 둔다. 같은 선택 화면에서 이동 결과 미리보기, 확정, 취소를 제공한다. 실패 화면에 남은 수량과 병목 위치를, 승리 화면에 실제 선적량을 표시한다. 입력은 키보드와 터치로 완주할 수 있게 한다.
- [x] 원화는 `current/artwork.json`의 `appearance:ssial-270C:front:none`, `appearance:wr-SWRM:front:none`, `appearance:ga-270C:front:none`가 지정한 경로·SHA를 사용한다. 세 이미지 로딩과 캐릭터 이름을 확인한다.
- [x] 규칙 및 브라우저 테스트를 실행하고, 데스크톱과 세로 화면에서 취소·재배치·도장 처리·다리 사용을 직접 해 본다. 탭을 오간 뒤 수레가 갑자기 부두에 도착하지 않는지도 확인한다. 결과와 최소한의 화면 증거를 남기고 첫 계약 시제품을 기록한다.

**플레이 진입점**　구현 후 `game-edition/`에서 `python3 -m http.server 8765 --bind 127.0.0.1`로 실행하고 `http://127.0.0.1:8765/spinoffs/contract-defense/`를 연다. 첫 플레이 검토에서는 출발 전에 약속을 자기 말로 설명할 수 있는지, 1/2에서 왜 이동하거나 남았는지, 한 판 더 하면 어떤 선택을 바꾸고 싶은지 확인한다.
