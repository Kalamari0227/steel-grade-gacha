# 캐릭터·원화 제작 계약

기준은 불변 `.omo/baseline/site/src/img`와 `asset-manifest.json`의 SHA256·ID·앞뒤 연결이다. 승인 시안 세 장을 [reference](reference/)에 보관한다. 기본 인물과 대표 특수 상태 원본 12장(poo, ssial, dogeum, p_phs_a/b, c_seddq, c_1180, g_hpf_a/b, eg_secc, wr_swrm, qp_1470)을 T3에서 직접 확인했다. 각 제작 담당은 자신의 나머지 원본도 개별로 열고 참조 이미지로 전달한다.

## 공통 제작 규격

금속 피규어의 둥근 작은 비율, 닦인 얼굴과 무광/브러시드 몸체, 승인 시안의 따뜻한 작업장 주광·약한 측면광을 공유한다. 각 소재는 원본 성질과 USE의 적용 장면·공정 맥락을 갖는다. 배경은 인물과 문양을 가리지 않으며 72px thumbnail에서도 실루엣이 읽혀야 한다. 연질=실패, LV상승=모든 물성 상승, 발광=규격 보증 같은 해석을 만들지 않는다.

생산 원화는 47개 모두 JPEG 480×720, 2:3 비율. 원본 `poo.jpg/ssial.jpg/dogeum.jpg`만 560×840이며 최종 목표와 구분한다. 기존44장은 480×720이다. 이름·LV·물성·대사·버튼·워터마크·카드 프레임은 원화에 넣지 않는다. 얼굴·문양을 안전영역 안에 두고 카드 crop 없이 보여준다. 최종 파일명과 `IMG`/`IMG_ALT` 연결은 바꾸지 않는다. 원본 단순 resize/필터만으로 redraw를 통과시키지 않는다. `originalSha256`은 영구 고정하고 새 파일 검토 후 `reviewStatus`와 선택적 `finalSha256`, `reviewEvidence`를 갱신한다.

공방은 별도 `src/uiimg/workshop.webp` 1개, 최대1200×480·최종240KiB 이하가 통과 조건이다. 기존 캐릭터가 기존 자동차를 조립하는 장면이다. 새 차종·완료되지 않은 수량·UI를 그림에 넣지 않는다. 그림은 홈에서 논리높이190px 이하로 표시한다. 레이어가 실제 분리되지 않은 JPEG/WebP에 다층 시차를 적용하지 않는다.

담당은 `.omo/artwork/staging/task-N`에 master/프롬프트/수정본을 보관하고 해당 `docs/design/production/*.md`에 원본 참조·새 해시·직접 시각 검토·반려와 수정 근거를 기록한다. live 입력 반영은 통합 담당에게 넘겨 직렬 빌드 후 같은 해시의 앱에서 카드 실크기·72px thumbnail·전후를 검토한다. 기술 검사는 `npm run verify:assets -- --group <group> --require-redraw`, 브라우저는 대응 `@art-*` 태그. 파일 검사가 인물 검토를 대체하지 않는다.

검수 통과 조건: ID/side/파일 정확, 정상 디코딩, 최종 크기, 새로운 해시, 같은 얼굴·문양·계열색, 과학적 의미, 텍스트 없음, 읽히는 thumbnail. 실패하면 해당 파일을 다시 생성·수정하고 동일 전체 그룹 시나리오를 재확인한다. PHS/HPF는 앞뒤 쌍을 나란히 보고 동일 인물인지 확인한다.

기존 이미지 매핑104개는 카드47+부품35+차8+보증14이다. 웹툰은 별도18 WebP(페이지15+썸네일3), 목록3항목(연재 안내/1화/2화)이며 새 회차를 만들지 않는다. 부품·차·보증·웹툰은 보존한다. 만화의 단순 그림과 피규어의 재질 차이는 허용하되 동일 머리·문양·얼굴 정체성을 유지한다.
