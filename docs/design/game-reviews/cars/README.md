# 자동차 미니어처 8종

기존 `t,h,n,m,s,z,b,d`를 각각 별도 내장 ImageGen 호출로 새로 제작했다. 전체 프롬프트, 생성 원본 경로, 원본/참조/출력 SHA는 `generation/{key}.json`에 있으며, PNG 원본 바이트는 `../masters/car/{key}.png`에 보관한다. 원형은 `src/carimg`와 기존 CARS/catalog다. 새 브랜드·차종·성능·진행 규칙을 추가하지 않았다.

| ID | 기존 힌트명 | 차체 분류와 구별점 |
| --- | --- | --- |
| t | 첫 글자 | 대형 미니밴: 높은 긴 상자형 캐빈, 슬라이딩 도어, 세로 그릴 |
| h | 합의 | 중형 세단: 낮고 긴 곡선 지붕, 가는 램프, 짧은 독립 트렁크 |
| n | 공책 | 소형 해치백: 짧은 휠베이스, 짧고 세운 해치, 검은 지붕 |

| s | 부지런한 놈 | 경형 크로스오버: 작은 수직 박스, 원형 램프, 아이보리 평지붕 |
| z | 다섯 번째 | 크로스오버 SUV: 흐르는 차체 곡면, 뾰족한 램프, 방패형 그릴 |

따뜻한 좌상단 조명과 차가운 보조광, 에나멜 도장과 은색 금속 장식으로 통일했다. 타이어는 검은 고무, 창은 좌석이 비치는 유리를 유지한다. 같은 차를 색만 바꿔 복제하지 않았다. 차종별 상품 사진 축척이므로 차량 간 실제 크기비를 뜻하지 않는다.

원본 전체를 비율 유지하여 1080×720 안에 축소한 뒤 1200×800 투명 캔버스 중앙에 둔다. 런타임은 lossless WebP이고 선언된 선택적 파생 자산 `car-thumbnail:{key}` 8개는 240×160이다. 덧칠·재색칠·수동 배경 제거·차체 자르기를 하지 않았다. 알파가 있는 바이트를 그대로 축소·인코딩했다.

`happy/{key}-comparison.png`는 원형/신규 master/실제 runtime/240px/72px 직접 비교다. `happy/all8-{light,dark}.png`는 두 배경의 식별성과 경계 검토다. `full/`은 전체 런타임 PNG, `72/`는 실제72×48 출력이다. `diorama/`에는 실제 신규 차고 배경 위의 데스크톱·모바일 배치 검토가 있다. 이 합성은 UI 구현이나 실제 사용자 보유 상태를 증명하지 않는 아트 배치 모형이다. 그림자·스탠드가 차량 알파에 구워져 있지 않다.

`receipts/`는 모든 출력·master·참조·검수 이미지의 현재 SHA를 결박한다. `catalog-binding.json`은 원래8차종의 힌트/차체와35부품 목록을 기록하며 앱 규칙은 수정하지 않는다. 독립 검토는 작업 증거 디렉터리에 별도로 기록한다.

검증: `node tools/verify-game-assets.mjs --group cars --review-root docs/design/game-reviews --report <evidence>/assets.json`. 병합 후에는 `--canonical`을 추가한다. 파생 썸네일8개를 포함하여16개를 검사한다. `--case car-negative --group cars`는 격리한 실제 생산 파일에 누락/중복/잘못된 ID 검수표/불투명 배경/손상 바이트/SHA/경로/파생 결박 오류를 주입하여 실제 CLI 거부를 확인한다. 차체 분류를 그림만으로 자동 인식하는 검증이라고 주장하지 않는다.
