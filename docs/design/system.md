# 스틸 그레이드 수집 공방 디자인 시스템

상태: T3 설계 계약 확정, 제품 구현·원화 제작은 후속 작업. 기준 SHA `6784048524c722b7d1057cb28e372b6cce5dc6cf`. 승인된 [공방](reference/01-workshop.png), [PHS](reference/02-card-phs.png), [제작](reference/03-crafting.png)을 직접 열어 추출했다. 데이터·저장 동작은 원본 함수가 기준이다. 상세 연결은 [기능 지도](../feature-map.md), [상태 계약](screen-states.md), [아트 바이블](art-bible.md), [자산 목록](asset-manifest.json)을 따른다.

## 1. 분위기와 정체성

따뜻한 밝은 작업대에서 금속 피규어들이 소재를 모으고 자동차를 조립한다. 은색 재질과 부드러운 작업장 조명은 원화에 집중하고 정보 영역은 차분한 종이색과 남색으로 읽힌다. 핵심 경험은 수집 → 소재 이해 → 재고 선택 → 부품 완성이다. 철강 실무자는 보유·비용을 빠르게 확인하고, 신입사원은 계열·사업등급·물성을 혼동하지 않아야 한다.

## 3. 글꼴과 숫자

`system-ui, -apple-system, BlinkMacSystemFont, 'Apple SD Gothic Neo', 'Malgun Gothic', sans-serif`를 사용하고 새 웹폰트 다운로드는 추가하지 않는다. 본문 16px/1.6, 보조 14px/1.5, 본문 강조 18px/1.5, 섹션 24px/1.3, 화면 제목 32px/1.2, 넓은 화면 주요 제목 40px/1.2. 제목 700, 버튼·수치 600, 본문 400. 작은 글자로 내용을 밀어 넣지 않는다. 수치에는 tabular-nums, TS에는 MPa, EL/RA에는 %를 명시한다. 한글 줄바꿈은 어절을 우선하고 긴 ID·백업 코드는 줄바꿈 또는 입력 영역 내부 스크롤로 처리한다.

## 4. 간격·배치·반응형

기본 간격 단위 8px: `--space-1:8px`, `--space-2:16px`, `--space-3:24px`, `--space-4:32px`, `--space-6:48px`. 좁은 화면 좌우 여백 16px, 섹션 간격 24px, 정보 카드 내부 16px. 최대 콘텐츠 폭 1200px, 넓은 화면 여백 32px. 일반 화면은 document가 스크롤을 소유하고, dialog가 열리면 해당 dialog 본문만 스크롤한다. 두 개의 중첩된 스크롤 카드 목록을 만들지 않는다.

승인 공방 시안은 제목·설정 → 자원 요약 → 공방 장면 → 조립 진행 → 추천 부품과 주요 CTA → 단일/10연 → 도감/차고 → 퀴즈/웹툰 → 4목적지 순서다. 추천은 PARTS 순서의 미완성+partReady 첫 항목이며 partPlan으로 비용을 계산한다. 제작불가이면 부족 소재 안내, 35개 완료면 자동차 선택으로 이어진다.

PHS 시안은 이름·계열/LV/재고 → 후열처리 원화 → 전후 선택 → 비교표 → 해설 → 사용처 → 제작 진입 순서다. 구현의 최초 앞뒤 상태는 기존 openCard의 상태 규칙을 유지하며 시안의 '열처리 후' 표시를 영구 기본값으로 하드코딩하지 않는다. 시안의 짧은 대사·가공한 문구보다 기존 c.line/c.alt.line 및 USE 값이 데이터 진실이다.

제작 시안은 부품명·진행 → 부품 위치/그림 → 슬롯별 후보와 재고 전후 → 총소비·부품 변화 → 도감 유지 안내 → 제작 CTA → 목록 복귀다. 샘플의 B 필러, 재고 1→0/2→1, 12→13/35는 고정값이 아니다. 원본 허용 후보 PHS/GA1470H와 CR980Y/GA980Y, partPlan(p,picks)/craft(key,picks)를 사용한다.

시안의 출하1·추가2·스크랩24·부품12/35·차고1/8·도감22/44는 설명용이다. pullsLeft/pullBaseLeft/S.extra/S.scrap/partCount/partsReadyCount/carsOwned/POOL에서 동적으로 구한다. 일반 도감 분모44와 QP 공개는 분리한다. 샘플 그림 속 수치·제목·아이콘·카드 프레임을 제품 이미지로 사용하지 않는다.

## 6. 동작과 연출

입력 피드백 120ms ease-out, dialog/전후 전환 180ms ease-out. 단일 공개: 봉인→계열 문양→카드→용도/재고, 기본 총 1.5초 이하·강조 포함 2.5초 이하. 10연은 즉시 전체결과 버튼을 처음부터 제공하고 상세 확인은 사용자가 넘긴다. 자동 10장 강제 시청 금지. 결과·소비·발견을 먼저 저장하며 skip/닫기/탭 이동/reload가 재추첨·이중지급하지 않는다.

`prefers-reduced-motion:reduce`는 공개·뒤집기·페이지 이동을 즉시 전환하고 smooth scroll·tilt를 없앤다. hover tilt는 포인터 기기에서 최대6도, 터치에는 없음. 방향센서 요청 없음. 단일 JPEG에 가짜 다층 parallax 없음. 허용 애니메이션은 transform/opacity 중심, 정보의 위치·내용이 입력 중 갑자기 이동하지 않게 한다. 제작 완료는 소비 후 부품 배치 피드백만 제공한다.

## 7. 표면과 깊이

배경→흰 정보면→dialog의 얕은 그림자 계층. 카드 `0 2px 8px rgba(23,40,60,.08)`, dialog `0 8px 24px rgba(23,40,60,.16)`. radius8(입력/버튼),16(정보패널/dialog), 1px 중립 경계. 금속 광택·foil은 카드 프레임 내부에서만 제한적으로 사용하고 작은 글자 뒤 질감·빛·입자 금지. 장식용 한쪽 색 띠와 카드의 두꺼운 색 테두리는 사용하지 않는다. 승인 시안의 파란 탭 밑줄은 구현에서 현재위치 글자·아이콘·톤 배경으로 표현한다. 키보드 focus-visible 테두리는 유지한다.

## 8. 접근성·검증·인계

색각 차이가 있는 사용자도 이름·약어·문양·상태 글자로 계열과 재고를 판별해야 한다. 키보드 사용자는 모든 후보·전후·모달·설정에 접근하고 닫은 후 이전 위치로 돌아간다. 큰 글자 사용자는 200%에서 동일 비용·오류를 읽는다. 동작 민감 사용자는 즉시 결과를 읽는다. 스크린리더는 이미지의 카드명/상태와 단위를 받으며 장식 그림은 빈 alt 처리한다. 오류는 저장이 보존되는지와 재시도/백업 행동을 명확히 말한다.

T3는 계약과 원본 대응 검토이며 실제 구현의 대비·키보드·반응형 통과를 주장하지 않는다. T5/T11–20 실제 브라우저 QA와 T21 성능 및 T23 통합 검증이 필요하다. 아직 승인한 접근성 예외·설계 부채는 없다. 현재 제품 미구현 상태는 완료된 UI로 오인하지 않도록 작업별 증거와 구분한다. 성능 기준은 계획의 기존 index 7,989,588B 대비 최종110%, 초기전송 baseline110%+240KiB, 준비시간 median125%를 따른다. 프레임워크·새 추적·계정·경제 규칙·학습효과 주장은 추가하지 않는다.
