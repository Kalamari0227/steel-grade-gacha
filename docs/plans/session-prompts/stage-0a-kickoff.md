# 0a단계 착수 프롬프트

새 세션을 프로젝트 루트(`/Users/ethanlee/Desktop/steel-grade-gatcha`)에서 열고, 모델을 Sonnet 5.5, 추론 강도를 medium으로 맞춘 뒤 아래 내용을 그대로 붙여 넣는다.

---

스틸 컴패니언 게임판 본 개발의 0a단계(기반 정리)를 진행해 주세요. 이 세션은 Sonnet 5.5 medium으로 진행하는 것이 프로젝트 규칙입니다. 현재 모델이 다르면 작업 전에 알려 주세요.

**배경.** 이 프로젝트는 철강 강종 캐릭터 수집 게임입니다. 승인된 원화로 만든 체험판(공방·출하·도감·카드·선행개발)이 2026-11-14에 품질 승인을 받았고, 이제 그 체험판 코드 위에 이전 게임의 나머지 기능(제작·차고·보증 장비·퀴즈·웹툰·백업 등)을 단계별로 옮기는 본 개발을 시작합니다. 전체 순서와 원칙은 `game-edition/docs/plans/game-development-plan-2026-11-14.md`에 있으니 먼저 읽어 주세요. 그 문서의 "개발 절차"와 "원칙" 절이 이 세션의 작업 방식입니다. 표현·연출의 계약은 `game-edition/docs/design/game-contract-revision-2026-11-14.md`, 화면 설계는 체험판 폴더의 `DESIGN.md`입니다.

**작업 위치.** 코드는 `game-edition/.omo/prototypes/steel-companion-full-art-remake/`에 있습니다. 숨김 폴더지만 Git에 추적되는 실제 제품 소스입니다. Git 저장소는 `game-edition/`이고 브랜치는 `게임용`입니다. 프로젝트 루트는 Git 저장소가 아닙니다.

**이 세션에서 할 일은 세 가지입니다.** 경제 규칙과 저장 형식은 이번 단계에서 건드리지 않습니다. 그 부분은 다음 0b단계에서 별도 세션으로 다룹니다.

1. 배포 스크립트. 지금은 `node export-pages.mjs <빈 경로>/game-preview`로 내보낸 뒤 그 결과를 임시 Git 저장소에서 `deploy/game-preview` 브랜치에 새 커밋으로 올리는 일을 손으로 합니다. 이 절차를 스크립트 하나로 묶어 주세요. 내보내기 대상 폴더는 저장소 밖의 임시 경로여야 하고(스크립트가 그렇게 검사합니다), 루트에 `.nojekyll`이 있어야 합니다. 스크립트는 푸시 직전에 멈추고 푸시 여부를 인자로 받게 해 주세요. 이 세션에서는 스크립트를 만들고 내보내기까지만 확인하며, 실제 푸시는 사용자가 승인한 뒤에 합니다.
2. `prepare.mjs`가 `data.json`의 `binding.experienceApproved`를 `false`로 고정해 씁니다. `game-edition/current/artwork.json`의 `experienceApproved` 값을 읽도록 고쳐 주세요. `export-pages.mjs`는 이미 같은 방식으로 고쳐져 있으니 참고하면 됩니다.
3. 탭 구조의 뼈대. 지금 체험판에는 공방과 도감 화면이 있습니다. 여기에 제작·차고·연구 세 화면의 자리를 추가해 주세요. 각 화면은 이름과 "준비 중" 안내만 있는 빈 화면이면 됩니다. 기존 화면 전환 방식(`views.mjs`, `app.mjs`)과 스타일 변수를 그대로 따르고, 키보드 조작·초점 이동·44px 조작 영역·390px 폭에서 가로 넘침 없음이라는 기존 기준을 지켜 주세요. 새 그림은 넣지 않습니다. 승인 목록(`current/artwork.json`)에 없는 그림은 쓸 수 없습니다.

**출발 기준선.** 2026-11-14 기준으로 단위 테스트 16/16, Playwright Chromium 12/12, WebKit 12/12가 통과하고 `python3 tools/verify-current-art.py`(game-edition 루트에서 실행)가 PASS입니다. 작업 전에 이 기준선을 직접 확인하고 시작해 주세요. Playwright 설정에는 서버 자동 실행이 없어서, 테스트 전에 체험판 폴더에서 `node server.mjs`(포트 8779)를 띄워야 합니다. 서버 없이 돌리면 전부 실패로 나옵니다. 끝나면 서버를 내려 주세요.

**끝난 상태.** 기존 테스트가 모두 통과하고, 새 탭 세 개에 대한 테스트(열림, 키보드 이동, 390px 폭)가 추가돼 Chromium과 WebKit에서 통과하며, `verify-current-art.py`가 PASS이고, 배포 스크립트로 내보낸 결과물이 로컬에서 열립니다.

**지켜야 할 것.**
- `src/`를 고치면 같은 파일을 `public/`에 반영하고 둘을 함께 커밋합니다. `node prepare.mjs`가 이 복사를 해 주지만 프로젝트 루트의 `.omo/artwork/` 보관소가 필요합니다.
- 테스트가 `qa-report.json`을 덮어씁니다. 보고서를 갱신할 의도가 없으면 커밋 전에 되돌립니다.
- 원화·승인 기록·세이브·백업·증거 폴더를 지우거나 옮기지 않습니다. 프로젝트 루트의 `STORAGE-POLICY.md`를 따릅니다.
- 큰 파일(`src/app_tpl.html`, `legacy.mjs`, `current/artwork.json`)은 통째로 읽지 말고 검색으로 위치를 찾아 필요한 범위만 읽습니다. 기호를 찾을 때는 `codegraph explore "<기호 또는 질문>"`을 먼저 써 보세요.
- 커밋과 푸시, 배포는 사용자가 요청할 때만 합니다.

**미리 알아 둘 상태.** 이전 세션의 변경은 모두 `게임용`에 커밋·푸시돼 있어 작업 트리가 깨끗한 상태에서 시작합니다. 시작할 때 `git status`로 확인하고, 예상하지 못한 변경이 있으면 손대기 전에 사용자에게 알려 주세요.

**끝나면 알려 줄 것.** 바꾼 파일, 실행한 검증과 결과(실패가 있으면 그대로), 확인하지 못한 것, 그리고 개발 계획 문서의 0a단계 줄에 적을 완료 날짜와 커밋을 정리해 주세요. 테스트 통과는 사용자 승인이 아니므로, 사용자가 직접 확인할 화면도 함께 알려 주세요.
