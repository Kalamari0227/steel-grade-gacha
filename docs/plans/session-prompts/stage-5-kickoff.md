**이 세션에서 할 일은 세 가지입니다.**

1. **원본 추출과 대조.** `source.mjs`의 `section()`으로 필요한 원본 구간을 그대로 추출합니다. 규칙을 새로 쓰지 않습니다.
   - 대상: `NOTICES`·`curNotice`, 행사의 상태 판정(예고·진행·종료)과 자동 안내 조건, `noticeSeen`·`promoSeen`·`promoDone`을 쓰는 문장, `bellOn`·`fireBell`의 판정과 `belledAt` 기록, `watchReady`의 전이 판정.
   - 화면 일(DOM, `Notification` 호출)이 섞인 함수는 3·4단계의 `judge`·`equip`·`settleQuiz`처럼 원본 문장을 그대로 담는 최소 함수로 감싸고, 감싼 방법과 원문이 아닌 줄을 `source.mjs`에 남깁니다.
   - 공지·행사 문구(제목, 본문, 기간 표기)는 원본 글자를 그대로 씁니다. 게임 이름이 들어간 문구("스틸 그레이드 가챠")를 어떻게 할지는 아래 확인 항목입니다.
   - `node prepare.mjs`로 다시 만들고, 생성 결과의 차이가 추가한 구간뿐인지 확인합니다. 기존 청크 해시와 `data.json`, `quiz.mjs`는 그대로여야 합니다.

2. **날짜·시각 경계 판정 (Opus 5.5 high).** 이 단계에서 올려서 할 부분입니다. 원본 소스를 직접 실행한 결과와 대조합니다.
   - 행사: 시작 직전·직후, 종료 직전·직후(1ms 단위), 앞 행사가 끝나는 시각에 다음 행사가 시작하는 이음매, 예고 구간, 마지막 행사가 끝난 뒤(지금의 실제 상태)에 `curPromo()`가 돌려주는 값과 그때의 화면.
   - 자동 안내: 처음 보는 행사에서 한 번만, 확인한 뒤에는 다시 뜨지 않음, 행사가 끝난 뒤 종료 안내가 한 번만(`promoDone`), 공지 확인이 행사 확인을 함께 처리하는 경우.
   - 공지: 새 공지가 있을 때 한 번만 자동으로 뜨고 `noticeSeen`이 같으면 뜨지 않음. 공지 목록이 비었거나 기간이 지난 경우.
   - 출하 알림: 한 번도 출하하지 않은 저장(`pullAt` 0)에서는 알리지 않음, 한 주기에 한 번만(`belledAt`), 갱신 시각 ±1ms, 페이지를 연 채 갱신 시각을 넘긴 경우와 닫았다가 갱신 뒤에 연 경우의 차이, 기기 시계가 뒤로 간 경우.
   - 시간대: 원본 행사 시각은 `Date.UTC`로 적혀 있고 주석은 KST입니다. 기간 표기 함수가 기기 시간대에 따라 무엇을 보여 주는지 확인해 주세요.
   - 불러온 저장의 `bell`·`belledAt`·`promoSeen`·`promoDone`·`noticeSeen`이 이상한 값일 때 원본이 어떻게 동작하는지 확인하고, 불러오기 검사(`engine.mjs`의 `validState`)에 넣을 항목을 정해 주세요. 0b·4단계의 `pullAt`·`quizAt` 처리와 같은 방식이어야 합니다(원본 정규화가 고치는 값은 정상, 원본이 오동작하는 값만 보류).

3. **엔진 명령과 화면.**
   - `engine.mjs`에 조회(현재 공지, 행사 상태와 기간·혜택, 알림 지원·권한·켜짐 여부)와 명령(공지 확인, 행사 안내 확인, 알림 켜기·끄기, 갱신 알림 기록)을 추가합니다. 저장을 쓰는 명령은 다른 명령과 같은 보호(다중 탭 검사, 손상 저장 보류, `commandBusy`, 저장 먼저 시도 후 결과 반환)와 `commandSafely`의 저장 잠금을 거칩니다.
   - 이 단계의 명령은 **경제값을 하나도 바꾸지 않습니다.** 바뀌는 것은 `noticeSeen`·`promoSeen`·`promoDone`·`bell`·`belledAt`뿐입니다.
   - 화면을 여는 것만으로 저장하지 않습니다. 자동으로 뜬 안내도 사용자가 확인·닫기를 눌렀을 때만 기록합니다(원본이 그렇지 않은 곳이 있으면 원본을 따르고 보고해 주세요). 3단계의 요구 굳히기(`pinOrder`)처럼 "보여 준 순간 저장"이 필요한지도 원본으로 판단합니다.
   - 권한 요청(`Notification.requestPermission`)은 사용자가 알림 버튼을 누른 뒤에만 합니다. 거부·미지원이면 켜진 것처럼 보이지 않게 합니다.
   - 토스트와 자동 안내는 다른 위층 창(동료 카드, 부품 상세, 장착 창, 퀴즈)이 열려 있을 때와 출하 연출 중에 어떻게 할지 정해 주세요. 4단계는 `tick()`이 `dialog[open]`일 때 다시 그리지 않는 방식으로 기다립니다.
   - 4단계 통합 검토에서 나온 지적을 되풀이하지 않습니다: 새로 뜨는 상자는 화면 안에 보이는 곳에 뜨고, 확인 창이 떠 있는 동안 뒤의 버튼이 눌리지 않으며, `tick()`이 다시 그리는 바람에 방금 쓴 안내 문구가 사라지지 않아야 합니다.

**화면 체계 (반드시 따릅니다).** 체험판 `DESIGN.md`의 "U4 밝은 출하 검사장" 절이 기준입니다.

- 스타일은 `prototype.css` 끝의 4단계 블록 뒤에 5단계 블록으로 이어 씁니다. 새 클래스는 처음부터 밝은 값으로 정의합니다.
