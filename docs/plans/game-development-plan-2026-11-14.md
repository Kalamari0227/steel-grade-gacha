## 원칙

1. 체험판 구조(`engine.mjs` 명령 → 저장 → 연출)를 유지하고 기능을 그 위에 옮긴다. 이전 게임 화면을 되살리지 않는다.
2. 경제·데이터 함수는 이전처럼 원본 소스에서 추출해 쓰고, 원본과 난수 결과가 일치하는지 대조한다. 규칙을 새로 쓰지 않는다.
3. 그림은 `current/artwork.json`의 승인 ID·SHA만 쓴다. 승인 목록에 없는 그림이 필요해지면 구현을 멈추고 아트 승인부터 받는다.
4. 단계마다 기능 지도의 해당 FM 항목을 테스트로 옮기고, 단위·Chromium·WebKit 통과 뒤 사용자 확인을 받는다. 테스트 통과를 사용자 승인으로 적지 않는다.
5. 저장을 건드리는 단계는 다중 탭·손상 저장·저장 실패 검증을 포함한다.
6. 단계가 끝날 때마다 배포본(`deploy/game-preview`)을 갱신해 같은 주소에서 확인한다.

## 확장 트랙: 레이싱과 디펜스 (2026-11-14 사용자 구상)

모은 것을 **쓰는 곳**을 만드는 확장이다. 차량으로 간단한 레이싱을, 캐릭터로 디펜스를 만든다. 본편 안의 미니게임으로 할지 별도 스핀오프로 할지는 각 기획 단계에서 정한다. 본편 0–8단계의 완성을 막지 않도록 아래 순서로 끼워 넣는다.

| 확장 | 시작 조건 | 쓰는 자산 | 새로 필요한 것 |
| --- | --- | --- | --- |
| A. 차량 레이싱 | 2단계(차고) 완료 뒤 | 승인 차량 8종, 부품 35 | 주행 시점의 차량 그림, 코스·배경, 조작·판정 규칙 |
| B. 캐릭터 디펜스 | 3단계(보증 장비) 완료 뒤 | 승인 캐릭터 47면·장착 외형 254, 보증 장비 14 | 적·경로·전장 그림, 스킬 효과, 편성·웨이브 규칙 |

### 진행 방식

각 확장은 같은 네 관문을 거친다. 앞 관문의 사용자 결정 없이 다음으로 넘어가지 않는다.

1. **기획서** — 한 판의 길이, 조작, 승패, 본편과의 연결, 필요한 새 그림 목록. 문서만 쓴다.
2. **조작 시제품** — 승인된 기존 그림만으로 한 판이 재미있는지 확인한다. 새 그림은 넣지 않는다.
3. **새 그림 제작·승인** — 본편과 같은 기준(대상 ID·SHA·사용자 승인)으로 받는다.
4. **구현·검증·배포** — 본편과 같은 테스트 기준.

본편 개발과 겹칠 수 있는 것은 1번(기획서)뿐이다. 2번부터는 위 시작 조건을 지킨다.

### A. 차량 레이싱

- 목적: 차고에서 끝나던 차량 수집에 다음 목표를 준다. 한 판 1–2분의 짧은 주행.
- 차량 성능은 가상 수치를 새로 만들지 않고, 그 차를 만들 때 쓴 부품과 소재의 실제 물성(TS·EL·RA)과 차급에서 끌어온다. 예: 고장력 소재 비중이 높으면 가볍고 단단함. 구체 규칙은 기획서에서 정한다.
- 회사·차명 비노출, 차급 정체성 유지라는 차량 원화 기준을 그대로 따른다.
- 현재 차량 원화는 진열용 3/4 미니어처라 주행 화면에 그대로 쓰기 어렵다. 주행 시점 그림이 새 아트 승인 대상이 될 가능성이 높다.
- 제안: **본편 안 미니게임**. 규모가 작고 차고와 바로 이어진다.

### B. 캐릭터 디펜스

- 출발 자료: [테이블 무역로 디펜스 시각 탐색 1차](../design/tabletop-trade-defense-2026-11-12-r1/concept-notes.md)(2026-11-12). 무역로와 수출 항구를 지키는 탁상 타워디펜스로, 관세·반덤핑·물류비 등을 적으로 형상화한 분위기 시안 3장이 있다. 실행 화면이나 승인 원화가 아니며 아직 Git에 추적되지 않았다.
- 캐릭터 역할은 계열과 실제 재료 특성에서 끌어온다(시안의 포오 가열·도금이 보호막·타래 밀쳐내기·큐피 파편). 보증 장비 장착이 스킬에 영향을 주는 구조를 검토한다.
- **계약과 부딪히는 지점:** 재계획 원칙 8과 계약 개정 대조표는 ATK·DEF·전투 수치를 금지한다. 디펜스는 피해량·사거리 같은 수치가 필요하므로, 본편에 넣으려면 이 조항을 개정해야 한다. 스핀오프로 분리하면 본편 계약은 그대로 둘 수 있다.
- 실제 국가·회사 표식을 쓰지 않는다는 시안의 기준을 유지한다. 반덤핑 등은 판타지 규칙이며 실제 제도의 재현이 아님을 게임 안에서도 구분한다.
- 적·전장·효과 그림이 모두 새로 필요해 A보다 규모가 크다.
- 제안: **별도 스핀오프**. 본편 수집 기록을 읽기만 하고, 저장과 경제는 분리한다.

### 본편 경제를 지키는 경계

- 확장의 보상이 출하 확률·RARE 가중치·스크랩 교환·QP 개발 조건을 바꾸지 않는다.
- 보상을 본편 자원으로 줄 경우 기존 한도(추가 출하 상한 등) 안에서만 준다. 한도를 넘는 새 재화는 만들지 않는다.
- 스핀오프는 별도 저장 키를 쓰고 본편 세이브에 쓰지 않는다.
- 유료 재화는 어느 쪽에도 넣지 않는다.

## 별도 과제: 효과음 교체

효과음은 본 개발 단계에 넣지 않는다. 현재의 Web Audio 합성음과 녹음 파일로 계속 진행하고, 품질을 높이고 싶을 때 독립 작업으로 교체한다.

- 교체 지점은 `reveal.mjs`의 `TIER_SOUND` 표와 `hero.mjs`의 합성음이다. 경제·저장·연출 시간과 분리돼 있어 어느 단계에서든 교체할 수 있다.
- 교체 시 확인할 것: 등급 네 단계의 구분, 음소거·스킵·감소모션에서의 중단, 음원 실패 시 시각 시계로 공개.
- 외주 발주나 유료 생성은 사용자가 따로 결정한다.

## 결정이 필요한 것

사용자가 따로 정하기 전까지 아래 제안을 기준으로 진행한다. 0a단계는 어느 결정에도 걸리지 않는다. 저장 키는 0b단계 착수 전에, 나머지는 해당 단계 전에 확정한다.

| 질문 | 제안 |
| --- | --- |
| 포크 원본의 새 기능(웹툰 3–7화, 요일별 증산, 퀴즈 힌트의 날)을 가져올지 | 가져온다. 원본 기획을 출발점으로 삼는 원칙과 맞고 경제 규칙을 바꾸지 않는다 |
| 정식 저장 키와 체험 세이브 처리 | 정식 키는 기존 계약의 `sgg_game_save_v1`. 체험 세이브는 체험용 지급이 섞여 있어 자동 이전하지 않는다 |
| 체험판 폴더를 저장소 루트로 옮길지 | 8단계까지 현재 위치에서 개발하고 마감 때 옮긴다. 이전 게임 `src/`는 대조용으로 그때까지 둔다 |
| 포크 `main`을 원본에 맞춰 올릴지 (현재 22개 뒤) | 6단계 전에 올린다. `게임용`에는 필요한 파일만 가져온다 |
| 레이싱과 디펜스 중 무엇을 먼저 할지 | 레이싱 먼저. 차량이 이미 있고 규모가 작다 |
| 레이싱·디펜스의 형태 | 레이싱은 본편 미니게임, 디펜스는 별도 스핀오프 |
| 디펜스를 본편에 넣을 경우 전투 수치 금지 조항 | 본편 조항은 유지하고 디펜스를 분리한다. 본편에 넣기로 하면 계약 개정을 먼저 한다 |
| 디펜스 시안 폴더(`tabletop-trade-defense-2026-11-12-r1`)의 Git 추적 | 기획 출발 자료로 커밋한다. 승인 원화가 아님을 폴더 문서에 이미 적어 두었다 |

## 개발 절차 (체험판 폴더 기준)

- 소스는 `src/`, 실행·배포 대상은 `public/`이다. `src/`의 html·mjs·css를 고친 뒤 같은 파일을 `public/`에 복사하고 둘을 함께 커밋한다. `node prepare.mjs`가 이 복사와 `data.json`·`legacy.mjs` 재생성을 한 번에 하지만, 프로젝트 루트의 `.omo/artwork/` 승인 보관소가 있어야 실행된다.
- 부품·차량·보증 장비·퀴즈처럼 `data.json`에 새 데이터가 필요한 단계는 `prepare.mjs`의 추출 범위를 넓힌다. 원본 함수는 지금처럼 `src/app_tpl.html`의 고정 SHA에서 추출한다.
- 이전 게임의 `src/game/*.js`(crafting·garage·equipment·collection·backup, 약 1,600줄)는 같은 기능을 한 번 모듈로 옮겨 본 결과물이다. 화면은 가져오지 않되 명령·판정 구조의 참고로 쓴다.
- Playwright 설정에 서버 자동 실행이 없다. 테스트 전에 체험판 폴더에서 `node server.mjs`(포트 8779)를 띄운다. 서버 없이 돌리면 전부 실패로 나온다.
- 테스트가 `qa-report.json`을 덮어쓴다. 보고서를 갱신할 의도가 없으면 커밋 전에 되돌린다.
- 배포: `node export-pages.mjs <빈 경로>/game-preview`로 내보낸 뒤 그 내용을 `deploy/game-preview` 브랜치에 새 커밋으로 올린다. 0단계에서 이 절차를 스크립트 하나로 묶는다.
- `prepare.mjs`가 `data.json`의 `binding.experienceApproved`를 `false`로 고정해 쓴다. 0단계에서 `current/artwork.json` 값을 읽도록 고친다.

## 검증과 기록

- 단계별 실행: `node --test qa/*.test.mjs`, Playwright Chromium·WebKit. 2026-11-14 기준 체험판은 단위 16/16, Chromium 12/12, WebKit 12/12 통과이며 `python3 tools/verify-current-art.py`(game-edition 루트)도 PASS다. 이 수치가 0단계의 출발 기준선이다.
- 저장·백업·복원과 장착 상태 정합성(0·3·7단계), 최종 통합 검토(8단계)는 프로젝트 지침의 상위 검토 대상이다.
- 테스트 trace는 실패 시에만 남기고, 단계 끝에 `python3 tools/cleanup-traces.py`로 후보를 확인한다.
- 단계가 끝나면 이 문서의 표에 완료 날짜와 커밋을 적는다.
