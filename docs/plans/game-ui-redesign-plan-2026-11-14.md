# 스틸 컴패니언 게임풍 화면 개편 계획 · 2026-11-14

**상태: 방향과 결정 항목 확정(2026-11-14), U1 착수.** 사용자가 U0 시안에서 C안을 고르고 아래 "결정" 표를 확정했다. 이 문서는 착수·커밋·배포 승인을 대신하지 않는다. [본 개발 계획](game-development-plan-2026-11-14.md)을 대체하지 않고 그 사이에 끼워 넣는 추가 트랙이다.

## 왜 지금 게임처럼 보이지 않는가

사용자 요청(2026-11-14): "정말 게임 느낌으로, 서비스 중인 수집형 게임처럼 바꾸고 싶다."

카드 원화와 출하 연출은 이미 게임 수준이다. 게임처럼 보이지 않는 원인은 그것을 담는 **껍데기가 웹 문서**이기 때문이다. 체험판 390px·1280px 화면 기준으로 확인한 것:

| 지금 | 서비스 중인 수집형 게임의 관례 |
| --- | --- |
| 종이색 바탕(`#f6f3ec`)에 흰 패널, 위에서 아래로 스크롤하는 문서 | 화면 전체가 무대. 배경 그림이 화면을 채우고 스크롤 없이 고정 |
| 상단 글자 탭(공방·도감·제작·차고·연구) | 하단 아이콘 독, 선택된 항목이 솟아오름 |
| "보유 자원 추가 출하 12회 스크랩 60" 한 줄 글 | 상단 HUD의 재화 칩(아이콘 + 숫자) |
| 공방에 코일 그림과 버튼 두 개 | 로비에 대표 동료가 서 있고 숨 쉬며, 주변에 메뉴가 떠 있음 |
| 상세가 흰 대화상자, 장착 외형은 `<select>` 드롭다운 | 전체 화면 캐릭터 화면, 장비는 슬롯 아이콘 |
| 도감이 흰 타일 격자 | 등급색 프레임을 두른 카드 격자 |
| 시스템 글꼴, 테두리 1px 평면 버튼 | 제목용 디스플레이 글꼴, 입체 버튼, 누르면 소리와 반응 |
| 화면이 즉시 바뀜 | 화면 전환, 타이틀 화면, 로딩 표시 |

원화를 다시 만들 필요는 없다. 승인 목록에 장면 10·무대 7·배경 6·프레임 5·아이콘 4가 이미 있어 대부분을 그것으로 채울 수 있다.

## 원칙

1. **장르 관례를 따르되 특정 게임을 복제하지 않는다.** 로비·HUD·독·배너·캐릭터 화면이라는 구조만 가져오고, 다른 게임의 화면 배치·아이콘·글꼴·색을 그대로 옮기지 않는다. 우리 무대는 금속 공방이다.
2. **껍데기만 바꾼다.** `engine.mjs`의 명령·저장·경제, 출하 연출의 길이와 등급 차등, 카드 글귀는 건드리지 않는다.
3. **유지하는 계약**: 유료 재화 없음, 전투 수치 없음(TS·EL·RA 그대로), 별 표시, 조작 영역 44px 이상, 키보드 조작·초점 복귀·화면 읽기 제목, 감소모션, 소리 기본 꺼짐.
4. **그림은 승인 목록만 쓴다.** 새 그림(독 아이콘·재화 아이콘·로고 등)이 필요하면 먼저 CSS·SVG 도형으로 자리를 잡고, 그림은 본편과 같은 승인 절차로 받는다.
5. **화면 하나씩 바꾸고 사용자가 직접 본다.** 테스트 통과를 화면 승인으로 적지 않는다.

## 끼워 넣는 위치

본 개발 1–4단계는 제작·차고·연구 화면을 새로 만든다. 옛 껍데기로 먼저 만들면 두 번 만든다. 그래서 **0b단계 앞에 U0–U2를 넣고**, 이후 단계의 새 화면은 처음부터 새 디자인 체계로 만든다.

```
0a (완료) → U0 → U1 → U2 → 0b → 1 → 2 → … → 8
                                  └ 각 단계의 새 화면은 U1 체계로 제작
                                                       U3은 8단계와 함께
```

## 단계

| 단계 | 내용 | 끝난 상태 |
| --- | --- | --- |
| **U0. 방향 시안** | 로비·출하 배너·캐릭터 화면 3장을 승인 원화로 만든 정지 시안(390px·1280px). 코드에 넣지 않는다. 색·글꼴·독 구성의 후보를 2안 이내로 제시 | 사용자가 방향 1안을 고름. 아래 결정 항목 확정 |

### U0 시안 (2026-11-14 작성, 같은 날 사용자가 C안 확정)

[시안 파일](../design/game-ui-redesign-2026-11-14-u0/index.html). `game-edition/`을 정적 서버로 띄우고 `docs/design/game-ui-redesign-2026-11-14-u0/index.html`을 직접 연다(루트 주소를 열면 이전 게임의 서비스 워커가 등록되어 시안 대신 이전 게임이 뜬다). 위쪽 검은 띠는 시안 조작용이며 게임 화면이 아니다.

- A안 강철 야간 / B안 노을 공방, 화면은 로비·출하·캐릭터. 390px 세로와 900px 이상 가로 배치를 모두 포함한다.
- 그림은 체험판 `data.json`의 승인 대상 ID로만 불러오고 복사하지 않았다: `scene:workshop:back`, `background:ga`, `stage:star-5`, `stage:heat-awakened`, `draw:coil-pack`, `icon:192`, `part:roof`, `item:arrow·iron·spark`, 도금이 1470H 외형 16종, 씨알 1470M·포오 PHS 기본 외형.
- 임시인 것: 독·바로가기 아이콘(SVG 도형), 스크랩 아이콘(CSS 도형), 글꼴(시스템 글꼴), 도감 수·재화 수·제작 진행도·게이지 길이(예시 수치), "공방장" 호칭.
- C안(같은 날 추가): 판·버튼은 A안의 짙은 금속판으로 통일하고 배경 밝기를 화면 역할로 나눈다. 로비는 밝은 노을 공방, 출하·캐릭터는 어둡게.
- 독 아이콘 시험(세 안 공통): 새 그림 없이 승인 그림을 축소해 넣었다. 도감 `thumbnail:ga-1470H:front`, 제작 `part:roof`, 공방 `draw:coil-pack`, 차고 `car:b`, 연구 `item:loupe`. 제작 칸의 빨간 점은 "제작 가능" 알림의 예시다.
- 출하 버튼은 눌러도 출하하지 않는다. 캐릭터 화면의 면 전환과 장비 슬롯은 실제 승인 외형을 바꿔 보여 준다.

### U1 구현 (2026-11-14, 사용자 화면 확인 대기)

체험판 `src/index.html`·`app.mjs`·`prototype.css`를 고치고 `public/`에 반영했다. 고정 무대, 화면별 배경, 상단 재화 칩, 하단 독(넓은 화면은 왼쪽 세로 독), 짙은 판과 황동·강철 버튼, 화면 전환이 들어갔다. 기존 화면의 내용과 배치는 그대로 새 껍데기 안에 있다. 세부는 [체험판 설계](../../.omo/prototypes/steel-companion-full-art-remake/DESIGN.md)의 "게임풍 껍데기 U1" 절.

- 시안과 다른 점: 독의 공방 칸이 가운데가 아니라 맨 왼쪽이다. 문서 순서와 키보드 이동 순서를 지키는 기존 테스트를 그대로 두었기 때문이다. 가운데로 옮기려면 그 테스트를 함께 고친다.
- 아직 안 한 것(U2): 밝은 로비와 대표 동료, 출하 배너, 등급 프레임 카드 격자, 전체 화면 상세와 장비 슬롯. 상세는 여전히 대화상자와 드롭다운이다.
- 검증: 단위 16개, Chromium·WebKit 각 21개 통과. 테스트 코드는 고치지 않았다. 390px·1280px 화면을 직접 찍어 확인했다. 320px 폭과 200% 확대는 확인하지 않았다.
- 알려진 불안정 테스트: Chromium의 "QP development plays the LV5 hero once…"가 `page.reload`에서 `net::ERR_ABORTED`로 가끔 실패한다. 고치기 전 코드(`ff418d8`)에서도 30회 중 3회 실패해 이번 변경과 무관하다. 카드 대화상자를 닫을 때의 `history.back()`과 새로 고침이 겹치는 것으로 보이며 원인은 확정하지 않았다. 테스트는 고치지 않았다. → 2026-11-15 안정화: 새로 고침 전에 `history.state.cardId`가 비워질 때까지 기다리게 했다(같은 파일 첫 테스트와 같은 대기). 고친 뒤 40회 연속 통과. 게임 코드는 바꾸지 않았다.

### U2 ①② 로비와 출하소 구현 (2026-11-14, 사용자 화면 확인 대기)

공방 탭을 로비(`#workshop`)와 출하소(`#ship`)로 나눴다. 로비는 밝은 배경에 대표 동료가 서고, 동료 카드에서 `로비 대표로 지정`으로 바꾼다. 세부는 체험판 설계의 "U2 로비와 출하소" 절.

- 저장: 지정했을 때만 `featured` 항목이 생긴다. 엔진 단위 테스트 2개(기본값·지정·보존, 미보유 ID 보류·다중 탭 거부)를 더했다.
- 고친 테스트: 출하로 시작하는 테스트의 진입 주소를 `/`에서 `/#ship`으로, `도감 열기` 버튼 대신 독의 도감 링크로, `공방으로` 뒤의 제목 기대값을 `코일 출하소`에서 `공방`으로 바꿨다. 로비·대표 지정 브라우저 테스트 1개를 더했다.
- 시안과 다른 점: 출하소에 1470급 동료 원화 대신 실루엣을 썼다(미발견 동료를 드러내지 않기 위해). 로비의 바로가기 세 개(선행개발·소리·설정)는 넣지 않았다. 소리는 상단에, 선행개발은 도감에 그대로 있다.
- 검증: 단위 18개, Chromium·WebKit 각 22개 통과. 390px·1280px에서 빈 로비·로비·출하소를 찍어 확인했다.
- 남은 U2: ③ 결과 진열 ④ 도감 등급 프레임 격자 ⑤ 전체 화면 상세와 장비 슬롯 ⑥ 선행개발 패널.

### U2 ③④⑤ 격자와 상세 구현 (2026-11-14, 사용자 화면 확인 대기)

도감과 10연 결과의 타일을 등급 프레임을 두른 작은 카드로 바꾸고, 상세를 전체 화면으로 펴고, 장착 드롭다운을 장비 슬롯으로 바꿨다. 세부는 체험판 설계의 "U2 도감 격자와 전체 화면 상세" 절.

- 시안과 다른 점: 상세에서 동료를 프레임 없이 무대에 세우지 않고, 승인된 카드 구성(프레임·별·글귀)을 그대로 크게 보여 준다. 카드 글귀와 프레임이 이미 승인된 표현이라 유지했다.
- 고친 테스트: 장착 선택을 드롭다운 `selectOption` 대신 슬롯 클릭으로 바꿨다(2곳). 네 장비 조합 검사에 슬롯 눌림 상태와 초점 확인을 더했다.
- 검증: 단위 18개, Chromium·WebKit 각 22개 통과. 390px·768px·1280px에서 도감과 상세를 찍어 확인했다.
- 남은 U2: 1회 결과 화면 배치와 선행개발 패널은 U1의 짙은 판 상태 그대로다. 필요하면 따로 다듬는다.

### 제목 글꼴: Hahmlet 확정·적용 (2026-11-14)

체험판 실제 화면(390px, 로비·출하소·도감·상세)에 `--display`만 바꿔 찍은 비교 화면으로 사용자가 골랐다. 결과: **Hahmlet**. 체험판 `src/fonts/`·`public/fonts/`에 허가서와 함께 넣었고, 단위 18개와 Chromium·WebKit 각 22개 테스트가 통과했다. 비교 화면과 나머지 후보 글꼴 9개는 지웠다.

- 후보: Black Han Sans, Do Hyeon, Pretendard Black. 사용자 허락을 받고 GitHub `google/fonts`(앞의 둘)와 `orioncactus/pretendard`에서 글꼴 3개와 허가서 3개를 `docs/design/game-ui-redesign-2026-11-14-u0/fonts/`에 내려받았다. 셋 다 허가서 본문이 SIL Open Font License 1.1임을 확인했다.
- 사용자 요청으로 같은 날 4종을 더했다: Gasoek One, Bagel Fat One, Gugi, Jua (모두 `google/fonts`, 허가서 본문 OFL 1.1 확인). 실제 화면에 얹어 본 결과 Gasoek One은 작은 글씨가 뭉치고, Gugi는 "1470H"의 H가 다른 글자처럼 보여 강종명에 맞지 않았다.
- 사용자 검토 "(Bagel Fat One은) 너무 아동스럽다"에 따라 둥글고 귀여운 계열(Bagel Fat One, Jua, Do Hyeon)을 제외하고 명조 3종을 더했다: Song Myung, Nanum Myeongjo ExtraBold, Hahmlet(가변 굵기). 모두 `google/fonts`, 허가서 본문 OFL 1.1 확인. 카드 글귀가 이미 명조라 제목을 명조로 맞추면 카드와 화면의 글씨가 통일된다.
- 축소(같은 날): 사용자 허락으로 fonttools·brotli를 임시 환경에 설치해 약 3.6MB 원본을 약 0.5MB woff2 축소본으로 바꿨다. 상용 한글 2,350자와 영문·숫자·기호, 현재 쓰는 모든 글자를 남겼다. 다시 만드는 방법은 체험판 폴더의 `subset-font.py`.
- Black Han Sans와 Do Hyeon은 굵기가 하나뿐이다. `@font-face`에 `font-weight:100 900`을 선언해 브라우저가 가짜 굵은 글씨를 만들지 않게 한다.

### 작은 화면·확대 점검 (2026-11-14)

로비·출하소·도감·상세·빈 탭·출하 연출·결과 여덟 화면을 다섯 크기에서 재고 찍었다: 320×568, 640×400(1280×800의 200% 확대), 320×256(400% 확대), 1280×400, 844×390(폰 가로).

- 결과: 모든 조합에서 가로 넘침 없음, 화면 밖으로 나간 조작 요소 없음, 44px 미만 조작 요소 없음(보정 뒤).
- 고친 것: ① 680px 이하에서 상표 고리가 32px 폭이던 것을 44px로 ② 360px 미만 로비의 목표·출하 버튼을 한 줄씩 쌓음 ③ 높이 480px 이하에서 하단 독의 그림을 빼고 글자만 남겨 78px → 54px ④ 넓고 낮은 화면(높이 620px 이하)의 세로 독도 글자만 남기고, 그래도 넘치면 독 안에서 스크롤.
- 남은 한계: 400% 확대(320×256)에서는 상단 HUD와 독 사이에 보이는 내용이 약 110px라 스크롤을 많이 해야 한다. 폰 가로(844×390)의 로비는 세로 배치 그대로라 목표·출하 버튼이 화면 아래로 내려간다. 둘 다 쓸 수는 있으나 다듬지 않았다.
- 검증: 단위 18개, Chromium·WebKit 각 22개 통과.

### U1에서 정하는 디자인 체계

| 항목 | 제안 |
| --- | --- |
| 바탕 | 어두운 강철색 무대 위에 공방 배경. 종이색 문서 바탕 폐기 |
| 패널 | 반투명 짙은 금속판 + 황동 테두리. 승인 프레임 5종을 9분할로 사용 가능한지 U0에서 확인 |
| 강조색 | 황동 `#f5cc75` 유지. 등급색(은·청·금·무지개)과 계열색 6종은 기존 값 유지 |
| 글꼴 | 제목·숫자에 디스플레이 글꼴 1종, 본문은 시스템 고딕. 글꼴 파일은 저장소에 넣어 직접 제공(오프라인 계약 유지) |
| 버튼 | 주 행동은 황동 입체 버튼, 보조는 강철 버튼. 누름·비활성·초점 상태를 모두 그림 |
| 재화 칩 | 출하 횟수·스크랩을 아이콘 + 숫자로. 숫자가 바뀔 때 튀는 동작 |
| 독 | 공방·도감·제작·차고·연구 다섯 칸. 가운데 공방이 가장 큼. 넓은 화면에서는 왼쪽 세로 독 |
| 전환 | 화면 간 0.2–0.3초 전환. 감소모션에서는 즉시 |

### 화면 비율

390px 세로를 기준 화면으로 삼는다. 넓은 화면에서는 무대를 화면 전체로 넓히고(가운데 폰 틀에 가두지 않는다) 로비·상세를 가로 배치로 재구성한다.
