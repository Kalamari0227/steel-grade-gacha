# Audio runtime integration

`GAME_AUDIO.boot(bridge)` is already called by GAME_BOOT after state restore. Definitions do not read S. The manager captures a frozen copy of the audio map only, calls no economy bridge function, and writes only the nested `audio` field of `sgg_game_preferences_v1`, preserving other preference fields. Invalid gain values cannot exceed unity. Every document waits for an explicit sound button gesture before creating AudioContext or fetching audio; remembered gains and mute are restored without autoplay.

The module mounts equally reachable `소리 켜기` and `무음으로 계속` actions, and settings controls for BGM, SFX, master mute and recovery. `play(cueId)` resolves false when muted, hidden, canceled, expired, unknown or unavailable. It never queues missed results. Invoke after the existing economic command and save attempt. `cancel()` invalidates pending cue loads and stops active effects; call on reveal skip, close, replacement or canceled presentation. `setMute(boolean)` and `setGain('bgm'|'sfx',0..1)` update preferences. `snapshot()` returns a detached diagnostic value, not live AudioNodes or economic state.

`setRoute(name)` selects workshop→workshop, dex→collection, research/learn/learning→collection, craft→craft, garage→garage. Existing destination links use pushState, so delegated menu clicks and Back/Forward are observed in addition to hashchange. Task24/31 should call setRoute after any other programmatic route transition and cancel when presentation work is invalidated. Current pre-Task24 core still normalizes craft/research URLs to workshop: tests exercise current workshop/dex/learn/garage navigation through real links and exercise future craft/research soundtrack selection through the explicit manager API. This is not a claim that the future screens already exist.

Audio is lazy per song/cue. Safety gain follows both category buses. The mix snapshot in the hash-bound audio map supplies defaults/caps; transition is400ms equal power, at most2BGM sources, six effects,100ms UI cooldown. Grand cues duck6dB with150ms attack and400ms release. Route tokens prevent stale asynchronous tracks and cue generations prevent canceled effects. Page hide stops sources and suspends the actual context; visible resumes only previously activated, opted-in and unmuted audio. Denied/hung resume offers a fresh gesture. Transport requests have a5second deadline, resume a1.2second deadline, and effect onset expires after1.5seconds.

Loop seconds come from the logical period and actual AudioBuffer.sampleRate. Decoder lengths are matched to independently retained/trimmed priming and padding, within two resampling frames. The selected loop always occupies a complete period of existing PCM. Guarded AAC includes1088 exact periodic tail frames before encoding; FFmpeg's1024 encoder delay yields2112 measured leading frames and960 padding. WebKit trims2112 leading frames; Chromium trims trailing padding and can round by one frame. A one-frame circular phase shift uses the existing periodic guard; no PCM is synthesized or time-stretched. Unknown lengths fail that variant and allow the next codec. Full production Opus/AAC decoding and leading/trailing reference correlation are tested at44.1/48k on Chromium/WebKit. Subjective listening and physical-device output are not established by clocks or PCM.

If browser output-rate resampling loses at most two frames from an otherwise exact logical period, the manager re-decodes the already fetched bytes in a temporary OfflineAudioContext at the manifest native rate. The full real AudioBuffer is then played by the live output context, which handles native source resampling. Diagnostics record actual buffer rate, live output rate and this fallback separately. No loop is shortened, no sample is invented, and no extra network request is made. Pending lifecycle/route tokens still discard canceled results.

Task31 cancellation extension: `snapshot().cueGeneration` is a monotonic cancellation token consumed by draw/craft/garage sessions. Each new presentation captures it; later timed cues are suppressed if any cancellation (including mute/SFX0) changed it, even after unmute. Visual progression continues. Existing audio methods and loop/mix behavior are unchanged.
